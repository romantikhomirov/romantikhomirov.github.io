# KNOWLEDGE.md — заметки по index.htm

Этот файл — памятка для будущих правок `index.htm`. Сайт — экспорт из Xara
(`Xara HTML filter v.9.3.0.51`), вся вёрстка построена на **абсолютном
позиционировании в пикселях** внутри контейнера шириной 1200px. Оригинальный
дизайн сознательно сохранён (пользователь отказался от полной пересборки на
современный responsive HTML/CSS — см. историю чата), поэтому все правки нужно
делать в том же стиле: руками подбирать `top:`/`left:`/`height:` в пикселях.

## Общая структура страницы

- `#xr_xrii` / `#xr_xr` / `#xr_xrc1` — три вложенных контейнера страницы.
  У всех троих (плюс фоновый `<span>` на строке ~55) синхронизирована общая
  высота страницы: `min-height` / `height` в px. **Если меняешь общую высоту
  страницы — обнови все 4 места одновременно** (сейчас это `9130px`).
- Контент — плоский список `<div class="xr_txt ...">` (текстовые блоки) и
  `<span class="xr_ar" ...>` (цветные скруглённые прямоугольники-подложки) и
  `<img class="xr_ap" ...>` (картинки), у всех `style="left:Npx;top:Npx;..."`.
- Почти для каждого `gte IE9` элемента есть парный `lt IE9` фоллбэк (закрыт в
  `<!--[if lt IE 9]> ... <![endif]-->`), обычно `<img>` вместо `<span>`.
  Исторически не критично для правок (браузеры давно не IE8), но если меняешь
  `top/height` у `gte IE9` спана — **синхронизируй те же цифры в соседнем
  `lt IE9` фоллбэке**, чтобы не путать при дальнейшем чтении кода.

## Ключевая механика: смещение текста внутри `xr_txt`

Это самое неочевидное место, из-за которого было больше всего итераций.

```html
<div class="xr_txt xr_s0" style="position: absolute; left:38px; top:862px; ...">
  <span class="xr_tl xr_s0" style="top: -51.31px;">Текст</span>
</div>
```

- `.xr_tl { position: absolute; white-space: pre; }` (см. `xr_main.css`) —
  то есть `<span>` внутри `<div>` **абсолютно спозиционирован относительно
  родителя**, а не течёт в потоке. Видимая позиция текста на странице:

  `visual_top = div.top + span.top`

- `span.top` — это шрифтовая поправка на baseline, она **отрицательная и
  зависит от класса шрифта** (см. ниже таблицу). Т.е. реальный текст рисуется
  ВЫШЕ, чем `div.top`, на величину этой поправки.
- Практическое следствие: чтобы текст оказался внутри цветной плашки
  (`xr_ar`) с `top: B`, нужно ставить `div.top = B + 62` (для `xr_s0`,
  крупный заголовочный шрифт) — это эмпирически выведенная формула по
  оригинальным блокам "Doodle God & Sequels" / "JoyBits" (`band top:4350`,
  `title top:4412`, диф = 62).
- Для многострочных абзацев (`xr_s2`) используется **один** `div`, а внутри
  него несколько `<span class="xr_tl xr_s2" style="top: Npx">` — построчно,
  с шагом ~38.13px между строками (см. паттерн `-29.93px / 8.2px / 46.33px /
  84.46px`). Смещение первой строки контента относительно верхней подложки:
  `div.top = card.top + 51` (выведено из блока Doodle God: card top:4470,
  текст top:4521, диф=51).

## Паттерн "заголовок блока + карточка" (WORK EXPERIENCE)

Каждая запись опыта работы построена одинаково:

1. Светлая плашка `#52A5DA`, `height:100px`.
2. Заголовок роли/проекта слева (`xr_tl xr_s0`) и название компании справа
   (`xr_tr xr_s0`), **оба на одном and том же `div.top` = `band.top + 62`**.
3. Небольшой отступ (~20px) до следующей карточки.
4. Синяя карточка `#428FC4` с описанием/картинками, `div.top` первой строки
   текста = `card.top + 51`.

Проверено на примерах: "WORK EXPERIENCE" (декоративная плашка top:690),
"Doodle God & Sequels" / JoyBits (band top:4350 → card top:4470),
"Casual HOPA Games" / JoyBits, "MODDING" / Ispitatel 4.

**Блок G5 Games и "Golden Prairies"/"Kosmos" тоже приведены к этому
паттерну** (после нескольких итераций правок в этом чате):
- G5: заголовок использует существующую декоративную плашку `top:690`
  (`div.top:752`; "Level Designer" слева `left:37`, "G5 Games"
  справа `left:1138`, подбирался вручную по просьбе пользователя),
  карточка описания `top:810 height:195` (`div.top:861` для текста).
- Golden Prairies/Kosmos: добавлена своя плашка `top:1025 height:100`
  (`div.top:1087` для обоих заголовков), затем большая карточка Kosmos
  `top:1145 height:3240`.
- **Правило пропусков: везде ровно 20px** (плашка → карточка, карточка →
  следующая плашка). Нижний внутренний отступ карточки равен верхнему
  (~21px): высота карточки = последняя строка + ~21px.

## Как безопасно менять/сдвигать блоки (техника)

Когда нужно вставить контент и "раздвинуть" всё, что ниже:

1. Определить порог `THRESHOLD` (первый `top`, который должен сдвинуться) и
   `DELTA` (на сколько px сдвигать).
2. Скриптом (Python/regex) пройтись по **всем** `top:(\d+)px` (только
   целочисленный формат без пробела — это абсолютные позиции; формат
   `top: -51.31px` с пробелом и дробным числом — это внутристрочные
   шрифтовые смещения, их трогать нельзя) и прибавить `DELTA`, если
   `val >= THRESHOLD`.
3. Обновить 4 места с общей высотой страницы (`min-height`/`height` ×3 +
   фоновый `span` height) на `старое_значение + DELTA`.
4. **Внимательно проверить элементы возле границы `THRESHOLD`** — если
   значение чуть меньше порога, но логически должно было сдвинуться вместе с
   остальными (как было с "Golden Prairies"/"Kosmos" при первом сдвиге —
   758/757 не попали под порог 810 и потом пришлось чинить отдельно),
   их придётся поправить вручную.

Пример команды (правился DELTA/THRESHOLD по ситуации):

```python
import re
DELTA = 120
THRESHOLD = 1070
content = re.sub(r"top:(\d+)px",
    lambda m: f"top:{int(m.group(1)) + (DELTA if int(m.group(1)) >= THRESHOLD else 0)}px",
    content)
```

## Прочие технические детали

- Видео YouTube (`<iframe src="https://www.youtube.com/embed/...">`) не
  показывается при открытии файла напрямую как `file://` (нет нормального
  origin, YouTube блокирует embed) — но нормально работает на `http(s)://`
  (GitHub Pages). Это не баг кода.
- Два YouTube-видео стояли в одной точке (одно перекрывало другое) —
  оставлено одно, `vgX_BrA3s7c`. Оба `<iframe>` имеют `loading="lazy"`, чтобы
  плеер не перехватывал фокус и не прокручивал страницу к "Full
  walkthrough" при открытии (причина не проверялась в браузере, гипотеза).
- Копирование текста со страницы "склеивает" соседние строки без пробела
  (из-за того, что строки — это отдельные `<span position:absolute>`, а не
  текст в потоке с настоящими пробелами/переносами). Если это важно для
  конкретной фразы — можно добавить пробел в конец первой строки вручную
  (сделано для фразы про Ispitatel 4 mod).
- Бэкап исходного (до всех правок) файла лежит в `index.old.htm.bak`.
- Ссылки `mobilegameslist` и `gamecompanieslist` (внешние подстраницы,
  папки `mobilegameslist/` и `gamecompanieslist/` рядом с `index.htm`)
  **больше не используются на главной странице** (блок с ними удалён по
  просьбе пользователя), но сами папки/страницы в репозитории остались
  нетронутыми.

### YouTube: заглушка вместо iframe

Страница "соскакивала" к видео при скролле: iframe YouTube при загрузке
(в т.ч. lazy-загрузке во время скролла) забирает фокус, и браузер прокручивает
страницу к нему. Теперь вместо `<iframe>` — `#ytfacade` (превью с i.ytimg.com +
кнопка play); настоящий iframe создаётся только по клику (`autoplay=1`).
Гипотеза о причине не проверена в живом браузере.
